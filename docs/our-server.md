# «Наш сервер» — инструкция администратора

Раздел «Наш сервер» в MkeiitLauncher устанавливает сборку модов для общего сервера и запускает игру с автоподключением.
Здесь описано только то, что уже реализовано (Фаза 1). Статус сервера, пинг и список игроков пока не реализованы.

## Как это работает

1. Лаунчер скачивает **манифест** — небольшой JSON-файл со списком модов. Сами `.jar` в манифесте и на нашем хостинге не хранятся.
2. Для каждого мода лаунчер одним запросом получает информацию из API Modrinth и находит файл, у которого
   **SHA-512 совпадает с манифестом**.
3. Файлы скачиваются только с `https://cdn.modrinth.com` встроенным загрузчиком Prism: с повторами, отменой, записью во
   временный файл и проверкой SHA-512 перед переносом в `mods/`.
4. Что обновлять, решается сравнением **реальных файлов** с манифестом, а не только по `packVersion`.
5. Удаляются и заменяются **только файлы, установленные сборкой**. Они перечислены в `server-pack.lock.json` в папке
   экземпляра. Моды, которые игрок поставил сам, не трогаются.
6. «▶ Играть на сервере» проверяет сборку, при необходимости создаёт экземпляр и докачивает моды, а затем запускает игру
   обычным способом Prism. Если в манифесте указан адрес, игра сразу подключается к серверу (Quick Play для 1.21.11).

## Где что настраивается

| Что | Где | Нужна пересборка? |
|---|---|---|
| Адрес манифеста по умолчанию | `Launcher_OUR_SERVER_MANIFEST_URL` в корневом `CMakeLists.txt` | да |
| Адрес манифеста у конкретного игрока | Настройки → API → «Наш сервер» → «Адрес манифеста серверной сборки» | нет |
| Адрес и порт сервера | объект `server` в манифесте | нет, достаточно обновить манифест |
| Адрес сервера у конкретного игрока | Настройки → API → «Наш сервер» → «Адрес сервера» (`host` или `host:port`) | нет |
| Версия Minecraft, загрузчик, моды | манифест | нет |

По умолчанию манифест читается из этого репозитория:

```
https://raw.githubusercontent.com/LIDFC/MkeiitLauncher/develop/server/manifest.json
```

Файл в репозитории: [`server/manifest.json`](../server/manifest.json). Репозиторий должен быть **публичным**, иначе
`raw.githubusercontent.com` не отдаст файл. Адрес манифеста принимается только по HTTPS.

## Формат манифеста

```json
{
  "formatVersion": 1,
  "name": "Our Server",
  "packVersion": "1.0.0",
  "server": {
    "address": "play.example.com",
    "port": 25565
  },
  "minecraft": "1.21.11",
  "loader": {
    "type": "fabric",
    "version": "0.19.5"
  },
  "mods": [
    {
      "name": "Fabric API",
      "source": "modrinth",
      "project": "P7dR8mSH",
      "versionId": "6qAuTtLR",
      "sha512": "852d3682c4f353fd0ca86546af8578513e8bcf628377fa9d49c556bc59c5024c69ab56c92fc6dfba11fed19e4316a3f5636e7e07fd3d96f7043b531aef59b637"
    }
  ]
}
```

| Поле | Описание |
|---|---|
| `formatVersion` | всегда `1` |
| `name` | название сервера; так же называется экземпляр в лаунчере |
| `packVersion` | версия сборки, например `1.2.0` (буквы, цифры, `.`, `+`, `-`, `_`) |
| `server.address` | адрес сервера без `https://`; пустая строка — адрес ещё не известен, игра запустится без подключения |
| `server.port` | порт, по умолчанию `25565` |
| `minecraft` | версия Minecraft, например `1.21.11` |
| `loader.type` | `fabric`, `quilt`, `forge` или `neoforge` |
| `loader.version` | точная версия загрузчика |
| `mods[].name` | название для интерфейса |
| `mods[].source` | пока поддерживается только `modrinth` |
| `mods[].project` | **ID проекта** Modrinth (8 символов, не slug) |
| `mods[].versionId` | **ID версии** Modrinth (8 символов) — закрепляет точную версию |
| `mods[].sha512` | SHA-512 файла этой версии |

Если манифест некорректен (ошибка в JSON, неверный ID, короткий хеш и т. п.), лаунчер показывает ошибку и **ничего не
меняет** в установленных модах.

## Как найти ID проекта, ID версии и SHA-512

Удобнее всего через API Modrinth в браузере.

1. **ID проекта.** Откройте `https://api.modrinth.com/v2/project/<slug>`, где `<slug>` — часть адреса страницы мода,
   например `https://api.modrinth.com/v2/project/fabric-api`. Нужное значение — поле `"id"` (для Fabric API это `P7dR8mSH`).
2. **ID версии и SHA-512.** Откройте список версий для нужной версии игры и загрузчика:

   ```
   https://api.modrinth.com/v2/project/fabric-api/version?game_versions=["1.21.11"]&loaders=["fabric"]
   ```

   Выберите версию с `"version_type": "release"`. Нужны поля:
   - `"id"` → `versionId`;
   - в массиве `"files"` у файла с `"primary": true` — `"hashes"` → `"sha512"` → `sha512`.

Пример для Fabric API 0.141.6+1.21.11: `versionId` = `6qAuTtLR`,
`sha512` = `852d3682…aef59b637` (полное значение — в примере выше).

Проверить хеш скачанного файла можно так:

- Windows (PowerShell): `Get-FileHash .\fabric-api-0.141.6+1.21.11.jar -Algorithm SHA512`
- Linux/macOS: `sha512sum fabric-api-0.141.6+1.21.11.jar`

Регистр букв в хеше не важен.

## Как выбрать версии Minecraft и загрузчика

- Все моды сборки должны поддерживать выбранную версию Minecraft и загрузчик — иначе лаунчер откажется ставить сборку и
  назовёт мод, который не подходит.
- Последнюю стабильную версию Fabric Loader для версии игры можно посмотреть здесь:
  `https://meta.fabricmc.net/v2/versions/loader/1.21.11` — берите первую запись с `"stable": true`.
- При смене `minecraft` или `loader` лаунчер сам переключит экземпляр на новые версии при следующей установке или запуске.

## Добавить мод

1. Найдите `project`, `versionId` и `sha512` (см. выше).
2. Добавьте запись в массив `mods`.
3. Увеличьте `packVersion`.
4. Опубликуйте манифест (см. ниже).

У игроков появится «🔄 Обновить серверную сборку» или «⬇ Установить N модов».

## Обновить мод

1. Замените у мода `versionId` и `sha512` на значения новой версии (`project` не меняется).
2. Увеличьте `packVersion` и опубликуйте манифест.

Старый файл мода будет удалён после успешной загрузки нового — если игрок его не изменял.

## Удалить мод

1. Удалите запись из `mods`.
2. Увеличьте `packVersion` и опубликуйте манифест.

При следующем обновлении лаунчер удалит файл этого мода, **только если** он был установлен сборкой и не изменялся. Если
игрок заменил файл, лаунчер оставит его на месте и перестанет им управлять.

## Опубликовать манифест

1. Отредактируйте [`server/manifest.json`](../server/manifest.json) в репозитории `LIDFC/MkeiitLauncher` (прямо в
   браузере на GitHub) и сделайте коммит в ветку `develop`.
2. GitHub кэширует `raw.githubusercontent.com` до ~5 минут — игрокам может понадобиться нажать «Проверить снова» чуть позже.

Перед публикацией проверьте JSON любым валидатором: ошибка в манифесте не сломает установленные моды, но обновиться никто
не сможет.

## Когда увеличивать `packVersion`

При **любом** изменении манифеста: добавили, обновили или удалили мод, сменили версию Minecraft или загрузчика, адрес
сервера. `packVersion` показывается игрокам («1.0.0 → 1.1.0»), но решение о загрузке принимается по реальным файлам, поэтому
забытое увеличение версии не приведёт к поломке — просто будет менее понятно, что изменилось.

## Настройки Minecraft-сервера

- **`online-mode=false`** в `server.properties` — обязательно, чтобы могли зайти Guest/Offline-аккаунты. Такие аккаунты не
  проходят онлайн-проверку, поэтому сервер в `online-mode=true` их не пустит.
- Для Фазы 1 других настроек не нужно. Для будущего отображения статуса и списка игроков понадобятся дополнительные
  настройки — они будут описаны вместе с реализацией.

Учтите: в `online-mode=false` сервер не проверяет, кто заходит, и любой может зайти под любым ником. Для небольшой группы
одноклассников используйте белый список (`white-list=true` и команда `/whitelist add <ник>`) или мод авторизации на сервере.

## Guest и Ely.by

- **Guest / Offline** — основной вариант для этого сервера, работает с `online-mode=false`.
- **Ely.by**-аккаунты тоже могут зайти на такой сервер: сервер не проверяет сессию. Отдельной настройки Ely.by на сервере
  не требуется.
- Аккаунт выбирается обычным образом (аккаунт по умолчанию или диалог выбора при запуске).

## Устранение неполадок

| Симптом | Что проверить |
|---|---|
| «Не удалось скачать манифест серверной сборки» | нет интернета; неверный адрес манифеста; репозиторий приватный; адрес не HTTPS |
| Ошибка про запись манифеста / версию / хеш | опечатка в манифесте: `project` и `versionId` — ровно 8 символов, `sha512` — 128 шестнадцатеричных символов |
| «Версия мода не найдена на Modrinth» | неверный `versionId` или версию удалили с Modrinth |
| «SHA-512 не совпадает» | `sha512` скопирован не от той версии или не от основного файла |
| «не поддерживает Minecraft …» / «загрузчик …» | выбранная версия мода не для этой версии игры или загрузчика |
| «Не удалось связаться с Modrinth» | Modrinth недоступен; уже установленные моды не меняются, играть можно с ними |
| «Файлы в папке модов мешают серверной сборке» | у игрока в `mods/` лежит свой файл с тем же именем, но другим содержимым — его нужно удалить или переименовать |
| Игра запускается без подключения | в манифесте пустой `server.address` и нет адреса в настройках игрока |
| Не пускает на сервер | на сервере `online-mode=true` или игрока нет в белом списке |

Подробности пишутся в лог лаунчера с префиксом `[ServerPack]` (категория `launcher.serverpack`). Состояние сборки хранится в
`server-pack.lock.json` в папке экземпляра; если его удалить, лаунчер не удалит ни одного файла, а при следующей установке
заново возьмёт под управление файлы с совпадающим SHA-512.
